一种工作模式：用户不经 [human review（人工评审）](./Human%20review.md)直接接受 [agent](./Agent.md) 的代码。Diff 被视为不透明——要紧的是程序行为如何，不是里面有什么。[Automated review（自动评审）](./Automated%20review.md)和 [automated check（自动化检查）](./Automated%20check.md)仍可运行；vibe coding 对两者都不表态。

该术语出自 Andrej Karpathy，他[在 2025 年初创造了它](https://x.com/karpathy/status/1886192184808149383)：「完全顺从直觉（vibes）」，「忘掉代码的存在」——描述你想要什么，接受返回什么，靠运行来判断。

Vibe coding（凭感觉编程）用检查换速度。读 diff 通常是 agent 驱动工作中最慢的一步，去掉它就移除了主要瓶颈。对于失败代价低的代码——[原型](./Prototyping.md)、一次性脚本、内部工具——这是合理的交换。风险随代码寿命和利害关系增长。

代价滞后到来。Vibe coding 的改动累积成一个没人读过的代码库，而行为是唯一被检查过的东西——所以任何行为暴露不了的问题，比如写进日志的密钥、缺失的边界情况、悄悄出错的数据处理，都会未经察觉地上线。第一次有人调试这个系统，就是第一次有人读这些代码。人工评审不在了，仍在运行的自动验证——测试、类型、自动评审——就是代码通过的唯一关卡。

_避免：_把 vibe coding 当作「低质量 AI 编码」的同义词——这个词指评审姿态，不指产出的代码。

_用法：_

「你读过它在 auth 流程里改了什么吗？」

「凭感觉编的——登录还能用，我就查了这个。」

「推之前读读 diff，在 auth 上凭感觉是密钥漏进日志的方式。」
