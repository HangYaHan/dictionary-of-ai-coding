description: 对话保真度不够、又需要真实物件可讨论时，让 agent 快速搭出粗糙版本。
---

让 [agent（智能体）](./Agent.md) 快速搭出某物的粗糙版本，用于对话保真度不够、需要一个真实物件来讨论的时候。

[Grilling（拷问式追问）](./Grilling.md) 在对话中解决设计决策。对话便宜，但保真度低：有些问题用文字答不了——交互手感如何、API 形状在真实调用代码里是否顺手、布局在真实数据规模下是否成立。访谈撞上一个问题，你诚实的回答是"不知道，我得看到它"。过了这一点，讨论就绕圈。改让 agent 把东西做出来、看它，再带着答案回到对话。

Agent 降低了构建成本，这才让此事可行。过去要花一天 mock 出来的粗糙版本现在只要几分钟，所以值得常规去做。这是 [human-in-the-loop（人在回路）](./Human-in-the-loop.md) 技术：原型做出来是给你反应用的。

你通常不会只看一轮。围绕原型迭代——反应、要求改动、再反应——每轮针对真实物件解决又一个决策，保真度高于对话所能及。

原型不必全是草货。你可以把真正在评估的部分做到生产质量，决策落地时，你反应过的组件或 API 就能转入真实代码库。这让 prototyping（原型构建）成为 [spec（规格说明）](./Spec.md) 可引用的实质材料。

_用法：_

"我们花了半小时争论向导该是一页还是三步。"

"文字定不下来——让 agent 把两个都做出原型。点一遍，五分钟就知道。"
